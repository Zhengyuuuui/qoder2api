- 审计日期：2026-11-10
- 审计对象：`qoder2api`（go.mod 声明 `go 1.22` / 实测工具链 go1.26.4，零第三方依赖）

## 一句话总体结论

**不建议直接上线**（P0 = 0，P1 = 5）。核心能力（多端点故障转移、模型级冷却/熔断降权、自适应节流、COSY 签名、风控遥测）**已真实落地且正确**，但存在 5 个 P1 必须先修：① 非法/不支持的代理配置静默直连（违反「配了代理绝不直连」核心不变量）② 存量部署升级后设备指纹整体漂移（形态 + 本机盐双重变更）③ 本轮全部新保护对存量部署默认关闭（bool 零值陷阱）④ 租约 10 分钟 TTL 误回收在飞长流突破并发上限 ⑤ 签到/刷新/凭证交换等非对话流量不走账号代理。另需注意：审计基线中「TrafficGuard 默认值正确」的论断**有误**（见下文），该误判可能导致团队误以为存量部署已受保护。

## 问题清单（按严重度）

### P1-1：非法 / 不支持的代理配置会静默直连（重点怀疑点 1）

- **现象**：`resolveAccountProxyInRegion` 在 URL 解析失败、scheme 不支持（socks5://）、URL 无 host 三种情况下都 `return ""`（空串=直连），仅打 ERROR 日志。
- **证据**：`internal/bridge/proxy.go:87-104`；:96 注释原文「the proxy is IGNORED and this account will connect directly」；配套测试 `proxy_test.go:113-119` 把该行为固化为预期（断言返回空串）。
- **影响**：用户配了 socks5 或拼错的代理，期望走代理，实际流量直连，真实数据中心出口暴露给上游——正是本轮要规避的后果，且只有一行 ERROR 日志（运维极易忽略）。
- **建议修法**（注意标准库不支持 SOCKS5，不能简单改成「失败」而忽略用户需求）：
  1. `resolveAccountProxyInRegion` 对「已配置但非法/不支持」的输入返回一个可区分的错误（而非空串），`bindProxy` 据此将该账号标记为「代理配置错误」，在控制台/诊断接口高亮显示并**拒绝发请求**（或拒绝入池），而不是静默直连；
  2. 对 socks5 明确给出「当前不支持，需用 http/https 代理或将请求导向一个支持 socks5 的本地转发」的可读提示，而非「IGNORED and connect directly」；
  3. 保留「未配置任何代理 = 直连」这一合法路径，仅对「已配置但非法」走失败分支。配套测试需反转断言。

### P1-2：存量部署升级后设备指纹整体漂移（形态 + 本机盐双重变更）

- **现象**：① `deriveID` 默认输出 UUIDv4 形态（旧为 32 位 hex）；② `EnsureMachineSalt` 首次启动自动生成本机盐混入派生种子。两者对已存在账号都会让 `machineid/machinetoken/machinetype` 整体改变，对上游等价于「账号换设备」。
- **证据**：`internal/cosy/fingerprint.go:81-88`（legacy 只回退形态）、`:54-62`（`saltedSeed` 混盐）；`account/store.go:264-284`（自动生成盐）；`main.go:96-102`（启动即加盐）。
- **影响**：升级即全员指纹漂移。形态有 `QD_DEVICE_ID_LEGACY=1` 回退，但**盐无开关**。
- **建议修法**：升级说明明示「升级前备份指纹/一次性设置 legacy」；给盐引入加显式确认或跳过开关（如 `QD_NO_MACHINE_SALT=1`）；指纹因「盐从无到有」而改变时打印醒目启动告警。

### P1-3：本轮全部新保护对存量部署默认关闭（bool 零值陷阱）

- **现象**：`TrafficGuard`/`AutoThrottle`/`SessionAffinity` 是 `Settings` 的 `bool`。`LoadSettings` 仅在 settings.json **完全不存在**时返回带 `true` 的字面量；文件**存在但缺字段**时，`var s Settings` 为零值，`json.Unmarshal` 只填文件里出现的字段，缺字段即 `false`，**没有任何「零值补默认」逻辑**。
- **证据**：`account/store.go:231-250`（默认值在 `if err != nil` 分支内，**不在** Unmarshal 之前）；`model.go:149/186/203` 注释明示「存量缺字段视为 false」；`guard.go:100-109`（`TrafficGuard=false` 仅团队/企业生效）、`throttle.go:101-106`、`affinity.go:82-87`。
- **影响**：对已有账号、真正处于风控压力下的存量部署，本轮新增的本地限流/自适应节流/会话亲和默认**全部关闭**。「默认 true」只对全新安装成立。这是「宣称有保护、实际默认没开」的典型偏差。
- **勘误**：审计基线称「store.go:240 在 json.Unmarshal 之前设 TrafficGuard: true，存量缺字段读到 true」——**不成立**。`store.go:240` 的 `TrafficGuard: true` 位于 `if err != nil { return ... }`（文件缺失）分支内，与 Unmarshal 是两条互斥路径；文件存在时走 `var s Settings`（零值）+ Unmarshal。代码自身注释（`:240`）也写明「存量文件缺该字段则读到的零值 false」。
- **建议修法**：为这三项提供显式迁移/回填，或在启动时检测「有账号但三项均未显式配置」打印醒目告警；长远把这些开关改成 `*bool`（nil=默认，参照 `ModelCooldown` 的 `Effective*()` 模式），消除「缺字段 vs 显式 false」歧义。

### P1-4：租约 10 分钟 TTL 误回收仍在飞的长流式请求（重点怀疑点 3）

- **现象**：`leaseLeakTTL=10min`，`AcquireLease` 锁内把「启动超 10 分钟未释放」的租约当泄漏删除。SSE 推理流可远超 10 分钟，在飞请求的租约被回收后 `len(leases)<limit` 重新成立，允许新请求进入。
- **证据**：`internal/bridge/guard.go:43`、`:143-150`；释放仅在 `defer ReleaseLease`（`bridge.go:699-700`）。回收机制已被 `guard_test.go:132-155`（`TestAcquireLeaseReclaimsLeakedLease`，构造 11min 旧租约后被回收）证明。
- **影响**：单账号并发上限（尤其 `ConcurrencyPerAccount=1` 最保守配置）在长流场景可被突破，闸门保护失效。
- **建议修法**：TTL 改为显著长于最长合法流生命周期（如 2h），或租约心跳续租（流式读取循环内定期 touch），或回收前校验该请求连接是否仍存活；TTL 与用户可调项关联而非硬编码 10min。

### P1-5：签到 / 刷新 / 凭证交换 / userinfo 等非对话流量不走账号代理（重点怀疑点 4）

- **现象**：账号代理只作用于 `BearerClient.httpClient`。以下流量各自用独立直连客户端：签到 `checkinClient`、PAT/刷新 `ExchangeJobToken` 内新建 `&http.Client{}`、userinfo `http.DefaultClient`、设备登录/轮询 `http.DefaultClient`。
- **证据**：`checkin.go:76-81` + `:214`；`internal/cosy/auth.go:68-69`；`internal/bridge/bridge.go:66-70`；`account/oauth.go:237/251/290`。`bindProxy` 仅作用于 `slot.client`（`bridge_pool.go:41-55`）。
- **影响**：同一账号「对话走代理出口、签到/刷新走数据中心出口」双出口并存，恰是被上游关联为「同一使用群体」的典型信号；且这些端点若对数据中心 IP 有风控，配了代理的账号在这些环节仍被判数据中心出口。
- **勘误**：模型列表**走代理**（`bridge.go:229` `slot.client.callGetCandidates` → `c.httpClient`），基线「模型列表未走代理」不成立。
- **建议修法**：至少把凭证交换/刷新/签到纳入账号代理（构造 client 后、签发/刷新前绑定代理，或让 `ExchangeJobToken`/`checkin` 接受带代理 client）；短期不改则明确文档化「代理仅覆盖对话与模型目录」。

### P2-1：fail-open 在过载时使并发上限失效

- `guard.go:171-179` 超时返回 `("",false)`，调用方不带租约继续发（`bridge.go:699` 忽略 ok）。持续过载下每个请求等满 30s 都放行，放行速率=到达−服务，并发无上限。建议给 fail-open 加「软上限」或软租约。

### P2-2：每请求多次读 settings.json（磁盘 ×~7，且写非原子）

- `AcquireLease` 内 4 次 `loadSettingsOrNil`（`guard.go:132/136/137/139`），叠加 throttle/MapModel/context 约 7 次/请求。`SaveSettings`（`store.go:252-262`）非原子写，并发读可能读到半截 JSON → 回落默认值（口径瞬时抖动）。建议单请求读一次传入各函数（或带 mtime 失效的缓存）；`SaveSettings` 改 temp+rename（与 `Pool.save` 一致）。

### P2-3：/health（无鉴权）暴露完整账号 ID

- `proxy_client.go:194-216` 存完整 `accountID`、`:242-279` 透出 `AccountID`；`health.go:36-49` 组装 Egress；`auth.go:185-202` 只放行 `/health`。本地账号 ID = `SanitizeID(上游 uid+显示名)`（`service.go:112`），内嵌上游用户 ID 与显示名，未截断。与 `health.go:15-17`「账号 ID 只给前 8 位」注释不一致（该截断只作用于 risk last 信号）。建议 Egress 段也截断到前 8 位，或把 Egress 移出无鉴权 `/health`。

### P2-4：排队「首字前一直等」默认开且无总时长上限

- `errors.go:71` 默认 true；`bridge.go:707-723` 仅 `!QueueWaitFirstToken` 时才按 `QueueMaxRetries` 封顶。单次等待有上限（`queueRetryAfter`→`QueueWaitCap`、`retryAfterFromDetail`→5min），次数无上限。建议即使 true 也设绝对总时长/总次数兜底。

### P2-5：代理 URL 的 path 未脱敏（重点怀疑点 2/5）

- `proxy.go:180-196` 保留 `u.Path`（含无密码时的 `u.String()`）。path 型鉴权 token 泄漏进日志/控制台/诊断。建议脱敏时对非空 path 打码。

### P3（观察项，逐条）

- **P3-1** `wrapProxyError` "proxy" 子串过宽（`proxy_client.go:140`），非代理错误若含 "proxy" 会被误标；仅影响文案。
- **P3-2** 客户端缓存永不淘汰（`proxy_client.go:47-90`），账号删除后 Transport 残留。
- **P3-3** 代理环境变量名取账号前 8 位（`proxy.go:41-42`、`:131-138`），前 8 位相同的两账号共享出口 env（低概率）。
- **P3-4** 遥测 `rejected` 合并 401/403 且凭证细分不体现在计数器（`risk.go:154-179`），聚合口径粗（信息未丢失，`last.detail` 有原文）。
- **P3-5** `last` 信号全局单条（`risk.go:101-103`），多账号诊断价值有限。
- **P3-6** 430→`version_gate` 只在 HTTP 状态字面 430 时命中（`risk.go:171`）；若上游把 430 嵌在 message 嵌套 JSON 里则永不触发。**待确认**：需抓真实上游响应确认 430 出现形式。
- **P3-7** `gofmt -l` 非空：`account/model.go`、`account/store.go`、`pool/pool.go`、`pool/selector.go`。
- **P3-8** 死代码：根目录 `pool/` 包全仓无 import；`bridge.go:20-26` 的 `qoderChatStreamURL`/`qoderModelListURL` 无调用点。
- **P3-9** `main.go:150-153` 把 `/api/identity/audit`、`/api/diagnostics/risk` 与 `/health` 归在「public」注释下，但 `isPublicPath` 只放行 `/health`，前两者实际需鉴权（行为更安全，注释误导）。

## 审计维度结论（逐项）

### 维度 1：并发闸门
- **不变量成立性**：在「成功拿到租约」的路径上，锁内「清理泄漏→判定名额→登记租约」三步原子完成（`guard.go:141-167`），`活跃租约 ≤ 上限` 成立；`guard_test.go:26-68` 并发 12 验证 `maxActive≤3`。
- **节奏整形等待在锁外**：`guard.go:152-158` sleep 前 `Unlock`，不持锁阻塞。✅
- **fail-open 一致**：与注释一致（`guard.go:25-26`），但过载下并发无上限（P2-1）。
- **闸门×节流协作**：`guardConcurrencyLimit` 取 `min(用户, ThrottleConcurrencyCap)`、`guardMinGap` 取 `max(用户, ThrottleMinGap)`，只紧不松（`guard.go:60-88`）。✅ 但降档时**在飞租约不做任何处理**（已登记的租约继续持有直到完成），这是「只影响新请求」的合理语义。
- **抖动随机性**：`mrand.Intn` 用全局 `math/rand`，全仓 `rand.Seed` 0 命中，go.mod `go 1.22`（Go 1.20+ 自动随机播种），非缺陷；未发现其他地方误用全局 rand 期望可复现。✅

### 维度 2：代理绑定
- **「配了代理绝不直连」**：不成立——非法/不支持/无 host 三条路径静默直连（P1-1）。代理可达性失败**确实请求失败不直连**（`proxyFunc` 非空永不返回 nil，`proxy_client.go:116-127`，`proxy_test.go:124-190` 验证）。✅（限合法配置）
- **缓存一致性**：无 `transportFor`/`clientFor`，统一 `clientForKey` + `proxyClientEntry{transport, proxy, clients}`（`proxy_client.go:28-90`），代理变更整条重建（`e.proxy != proxy`），无「transport 已换 client 挂旧」窗口。✅
- **未脱敏代理 URL 泄漏面**：`proxy_test.go:239-287` 覆盖密码脱敏；诊断/日志均经 `RedactProxyURL`。唯一残留是 path 未脱敏（P2-5）。
- **client.Do 直连遗漏**：对话/模型目录全走 `c.httpClient`；但 userinfo（`bridge.go:70`）、PAT 交换（`auth.go:68`）、签到（`checkin.go:76`）、oauth（`oauth.go`）用 `http.DefaultClient`/独立 client，属 P1-5。

### 维度 3：端点故障转移
- **转移边界**：`shouldFailoverEndpoint`（`client.go:364-377`）传输层+5xx 换、4xx/业务不换。✅
- **冷却阈值/重置**：`endpoints.go:96-128` 连续 3 次→5min 冷却、成功清零。✅
- **候选顺序**：国际版 chat `api1→api3→api2`、model list `api2→api1`，与 region.go 注释声明一致（无法对官方客户端做外部验证，标注「以配置声明为准」）。✅（待外部确认）
- **签名 path 同步（高危点，已排除）**：`openStreamCandidates`（`client.go:481-511`）遍历候选 `u`，逐个调 `openStreamLinesOnce(ctx, u, ...)`，其内部 `pathSig := PathSigFrom(fullURL)`（`client.go:517`）由**实际正在尝试的候选 URL** 派生，签名 path 与实际 URL 严格同步；`callGetOnce`（`client.go:320`）同理。切换端点不会导致签名 path 失配。✅

### 维度 4：风控遥测
- **atomic 与打点唯一**：计数 `atomic.Int64`、`last` 用 mutex（`risk.go:60-68`）；唯一打点入口 `RecordRiskSignal`（`risk.go:80`）；`risk_test.go:164-195` 100 goroutine 总数精确。✅
- **分类正确性**：429→rate、401/403→rejected、10605/isQueued→queue、430→version_gate；RESOURCE_LIMIT 双语义正确拆分（重点怀疑点 10 不成立）。430 出现形式待确认（P3-6）。
- **/health 泄露**：见 P2-3（完整账号 ID）。token/密码/代理凭据未泄露（均脱敏）；上游 detail 截 200 字符（`risk.go:32`），200 字符可能含模型名/部分 token，属低风险观察项。
- **/health 零上游请求**：`handleHealth`（`health.go:36-49`）只读 `RiskSnapshot/EndpointStatuses/RegionEgressStatuses/PoolSummary`，均为内存态+`os.Getenv`。✅

### 维度 5：模型级冷却 / 熔断 / 降权
- **判定入口唯一**：`availableFor`（`pool.go:148-171`）为唯一可用性判定，`PickForModel`/`pickSlotWithAffinity` 均走它。✅
